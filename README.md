این مخزن مربوط به پروژه دوم بوت‌کمپ هوش مصنوعی کوئرا در بهار ۱۴۰۵ است.

پروژه شامل دو مسئله اصلی است:

1. تشخیص وقوع تصادف از روی ویدئو با استفاده از بینایی ماشین
2. تحلیل نظرات محصولات آمازون و پیش‌بینی امتیاز کاربران با استفاده از پردازش زبان طبیعی

# مسئله اول: تشخیص تصادف

## تعریف مسئله

هدف این بخش، طراحی یک سیستم دسته‌بندی دودویی است که با دریافت یک ویدئوی کوتاه تشخیص دهد آیا در آن تصادف رخ داده است یا خیر.

مجموعه‌داده این بخش شامل ویدئوهای کوتاه و متادیتای مربوط به آن‌ها است.

مجموعه‌داده:

[مجموعه‌داده Nexar Collision Prediction](https://huggingface.co/datasets/nexar-ai/nexar_collision_prediction)

برچسب هر ویدئو بر اساس ستون `time_of_event` تعیین می‌شود:

- وجود مقدار در `time_of_event`: تصادف رخ داده است.
- مقدار خالی یا `NaN`: تصادفی رخ نداده است.

از آنجا که ورودی مدل ویدئو است، ابتدا تعدادی فریم با فاصله زمانی مشخص از هر ویدئو استخراج می‌شود. سپس مدل‌های تصویری و زمانی روی این فریم‌ها آموزش داده می‌شوند.

## وابستگی تسک‌های CV

وابستگی اصلی مراحل به شکل زیر است:

```text

          ↓

مدل پایه        مدل زمانی
```

- ارزیابی نهایی علی به پیش‌بینی‌های مدل بنیامین و فاطمه وابسته است.
- هر عضو باید پیش از دریافت خروجی مرحله قبلی، ساختار Notebook و کدهای مستقل خود را آماده کند.

## وابستگی تسک‌های NLP

وابستگی اصلی مراحل به شکل زیر است:

```text
داده پاک‌سازی‌شده و Split مشترک — فاطمه
                  │
     ┌────────────┼────────────┬────────────┐
     ↓            ↓            ↓            ↓
تحلیل محصولات   Baseline    تحلیل گارانتی   مدل عمیق
بنیامین          علی          مهیا           عباس
     │            │                           │
     └────────────┴──────────────┬────────────┘
                                 ↓
                    مقایسه و جمع‌بندی نهایی
```

نکات مهم:

- بنیامین، علی، مهیا و عباس برای اجرای نهایی به داده پاک‌سازی‌شده فاطمه نیاز دارند.
- این چهار نفر پس از آماده‌شدن داده می‌توانند به‌صورت موازی کار کنند.
- عباس برای شروع مدل عمیق لازم نیست منتظر تکمیل مدل پایه علی بماند.
- نتیجه مدل پایه فقط برای مقایسه نهایی مورد نیاز است.
- تحلیل گارانتی مهیا پس از آماده‌شدن داده می‌تواند مستقل انجام شود.
- تمام مدل‌ها باید از Split مشترک استفاده کنند تا مقایسه نتایج معتبر باشد.

# قوانین همکاری

- هر Notebook یک مسئول اصلی دارد.
- تمام اعضا باید به Notebookهای پروژه دسترسی داشته باشند.
- هر عضو باید تغییرات مربوط به تسک خود را ثبت کند.
- هیچ عضو نباید بدون هماهنگی، بخش اصلی Notebook عضو دیگر را حذف یا بازنویسی کند.
- قبل از شروع کار، آخرین نسخه پروژه دریافت شود.
- قبل از تحویل هر مرحله، Notebook از ابتدا اجرا شود.
- تمام تصمیم‌های مهم باید مستند شوند.
- تمام خروجی‌های مهم باید در Notebook باقی بمانند.
- هر خروجی باید برای نفر بعدی قابل استفاده باشد.
- استفاده از مدلی که اعضای تیم توانایی توضیح آن را ندارند مجاز نیست.
- هر تسک باید حداقل توسط یک عضو دیگر بررسی شود.
